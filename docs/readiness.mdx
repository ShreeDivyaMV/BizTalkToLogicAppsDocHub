# Understand the interface you are replacing

Gather the source and runtime evidence needed to implement the same behavior in Standard: schemas, maps, pipeline stages, bindings, custom code, message samples and failure cases. The controls below highlight design choices rather than eligibility or delivery estimates.

## Resolve the technical unknowns

### Source and message contracts

- Source is available and the inventory can be reconciled with production.
- Inputs are sanitized and access is approved.
- Referenced schemas, maps, assemblies and pipeline components are available.

### Runtime behavior

- State, correlation keys, ordering and side effects are understood.
- Missing dependencies and unsupported constructs are recorded.
- Representative test evidence exists.

### Target implementation

- Architecture and hosting are selected.
- Gaps have explicit dispositions and acceptance tests.
- Test dependencies are isolated from production.

## Estimate complexity without false precision

Use the following to identify engineering experiments, not support labels or person-day commitments.

| Band | Typical signals | Next estimation activity |
| --- | --- | --- |
| Simple | A bounded flow, standard connectivity, little custom behavior | Implement a pilot and measure actual effort |
| Medium | Transformations, multiple endpoints and operational dependencies | Validate a representative pattern and price its remediation |
| Complex | Stateful correlation, custom code, B2B or strong non-functional constraints | Run a time-boxed engineering spike before committing a wave |
| Exceptional | BAM/ESB redesign, unsupported dependencies or broad cross-system transactions | Produce a separately reviewed architecture and delivery plan |

Estimate discovery, remediation, testing, partner coordination and cutover separately. Calibrate ranges with observed pilot throughput and named team capacity; no duration or staffing number is reliable from artifact counts alone.
