# You don't have to navigate this alone

## Contact the right team

| Topic | Published contact route | Scope |
| --- | --- | --- |
| Production/product issue | Azure portal **Help + support**; [create a support request](https://learn.microsoft.com/en-us/azure/azure-portal/supportability/how-to-create-azure-support-request) | Response and eligibility depend on the applicable support plan |
| Pricing, procurement or commercial enquiry | [Contact Azure sales](https://azure.microsoft.com/en-us/contact/) | Sales contact, not an incident escalation queue |
| Agent bug or feature request | [Migration Agent issues](https://github.com/Azure/logicapps-migration-agent/issues) | Public tooling triage, not an SLA-backed support request |
| Technical community question | [Microsoft Q&A](https://learn.microsoft.com/en-us/answers/tags/134/azure-logic-apps/) | Public guidance; omit confidential information |
| Assessment/engineering engagement | Your existing Microsoft account-team contact | Confirm whether assistance is available and its agreed scope |
| Implementation partner | [Microsoft partner directory](https://appsource.microsoft.com/en-us/marketplace/partner-dir) | Independently negotiated delivery engagement |

No dedicated migration mailbox, named engineer or free-assistance guarantee has been verified for this hub. Use your established private contact route for confidential source, bindings and customer data.

Start with the product reference for the failing workflow action, transformation or connection. Use product support for runtime issues, the Agent repository for generation/tooling defects, and specialist help for implementation problems. Availability, scope, eligibility and commercial terms must be confirmed with the provider.

## Request an engagement with a useful intake pack

Include:

1. Your business objective, lifecycle exposure and requested completion window.
2. Affected interfaces, message contracts, runtime settings and a minimal sanitized reproduction.
3. Source availability, discovery findings and known unsupported patterns.
4. Hosting, networking, compliance and data-locality constraints.
5. Pilot evidence, expected delivery capacity and current blockers.
6. A specific request: architecture review, tooling defect triage, assessment or delivery.

Use approved private channels for confidential material. Never publish credentials, production payloads, complete connection strings or unredacted bindings in GitHub or Q&A.

## Confirm scope explicitly

Before engaging, ask who owns discovery, remediation, custom code, test evidence, platform provisioning, production deployment, partner certification, cutover and retirement. Document deliverables, exclusions, response expectations and acceptance criteria.

There is no verified universal "free migration engineering" or paid support eligibility promise in this hub.
